  Как работает

  1. python -m agent.main --ticket 1 --repo <student> --tests-dir 
     <codementor/tests/tickets> --test-output test-output.txt --log service.log 
     --out comment.md
  2. Первое сообщение модели содержит текст тикета, вывод тестов и хвост лога.
     Дальше идёт цикл: модель вызывает инструменты, мы их выполняем и возвращаем
     результат.
     - list_files(path) и read_file(path) работают только внутри корня
       репозитория студента и только на чтение. Каталоги .git и файлы .env
       закрыты, вывод обрезается.
     - get_logs(contains?, max_lines?) отдаёт хвост лога или строки, где
       встречается заданный текст.
     - run_test(test_name?) повторно запускает pytest для тестов этого тикета с
       таймаутом. Сервис в CI в этот момент уже запущен.
  3. После 10 вызовов инструментов модель делает последний запрос уже без
     инструментов и обязана дать ответ.
  4. В comment.md попадает метка <!-- codementor:ticket=1;mode=debugging;level=1
     --> и подсказка. Простая защита: блоки кода (```) вырезаются.

  Решение, которое отличается от PLAN.md (предлагаю записать в D14)

  post_comment не будет инструментом модели. Агент только пишет comment.md, а
  публикует его шаг workflow через gh pr comment, как сейчас делает заглушка.
  Почему так:
  - комментарий гарантированно один;
  - метку ставит код, а не модель;
  - у агента нет GitHub-токена, то есть он полностью read-only.

  Альтернатива: инструмент post_comment с вызовом GitHub API. Но тогда модель
  может вызвать его дважды или вообще забыть вызвать.

  Изменения в check.yml

  - При result == failed: установить agent/requirements.txt и запустить агента с
    OPENROUTER_API_KEY: secrets... и CODEMENTOR_MODEL: vars..., затем
    опубликовать comment.md.
  - Если агент упал (ошибка API, пустой ответ), публикуется прежний комментарий
    mode=check, чтобы студент не остался без результата.
  - При passed и build_failed пока остаётся текущий комментарий: review mode
    будет позже.
